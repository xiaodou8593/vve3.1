# vve:plane

水平介质平面。用一块水平板代替方块，给物体提供地面、平台这类碰撞面，范围可以任意大，不受方块边界限制。命中后输出的是实心接触响应：位移修正、支持力、摩擦、反弹，并置 `surface_response = 1` 让物体做姿态修正；不含浮力。

实例是 marker（`tag=vve_plane`），`vve_material_type` 为 `3`，命中时 `material_response` 也是 `3`。`3` 不是平面专用编号：`slope_xp`、`slope_xn`、`slope_zp`、`slope_zn` 也都是 `3`，这一类统称区块索引介质，按碰撞点所在区块筛候选；`vve:call_material` 靠实例上的 `module_id` 把调用分派到具体模块。实现位于 `data/vve/function/plane/`，函数前缀 `vve:plane/`。

## 用它之前

- `vve:plane/init` 要先跑过。它建十二个目标（`x_min`、`x_max`、`z_min`、`z_max`、四个 `chunk_*`、`base_layer`、`nvec_x`、`nvec_y`、`nvec_z`），并把 `#vve:plane/ module_id` 注册进 `module_control`。没有这一步，marker 仍会生成，但坐标目标缺失、实例数据不完整，探测时分派不到。
- `y`、`x`、`z` 不在 `plane/init` 里创建，它和物体模块共用项目的位置目标。
- 平面是静态介质，没有每帧逻辑：`main` 只做 `_get` 加 `_store`；`tick` 没有接进任何 tick 调度，不调用也不影响。
- 板面只能是水平的。`nvec` 固定为 `(0, 10000, 0)`，要倾斜面用 `slope_*`。

## 数据

实体分数。`1w` 是 ×10000 定点。

| 分数 | 单位 | 含义 | 来源 |
| --- | --- | --- | --- |
| `y` | 1w | 板面上表面的高度 | 手填 |
| `x_min`、`x_max` | 1w | 板在 x 方向的绝对闭区间端点 | 手填 |
| `z_min`、`z_max` | 1w | 板在 z 方向的绝对闭区间端点 | 手填 |
| `base_layer` | 1w | 判定容差深度：表面以下多深仍然算命中 | 手填 |
| `chunk_x_min`、`chunk_z_min`、`chunk_x_max`、`chunk_z_max` | 区块 | 范围覆盖到的区块 | `_calc_chunk_range` |
| `nvec_x`、`nvec_y`、`nvec_z` | 1w | 法向量 | `_calc_nvec` |

后两行不要手填，由两个 `_calc_*` 函数生成。

命中要两条同时成立：水平方向落在闭区间内，并且 `y - base_layer ≤ c_y ≤ y + 1000`。上限比表面高 0.1 格，这个 0.1 来自全局常量 `vve_slope_block_d`（`-1000`），斜面共用，改它两边一起变。

`base_layer` 是判定容差，不是可见厚度，预览画出来永远是一块薄板。板下方 `base_layer` 以内也算命中：物体从下方靠近时同样拿到响应，并被推回表面。所以它有两面：调大能降低快速物体一帧穿过的可能，但会让板下更深处的物体也被抓住。按物体的单帧下移 `d` 取 `base_layer ≥ d - 0.1`；平台下方有其他物体时不要取大。

## 生成平面

下面的例子是一块中心在 x=200、z=50、边长 64 格、表面 y=64、容差 5 格的板。`x_min` 等四个值是绝对坐标不是半宽，半宽 32 对应加减 `320000`。

```
function vve:plane/init
scoreboard players set y int 640000
scoreboard players set x_min int 1680000
scoreboard players set x_max int 2320000
scoreboard players set z_min int 180000
scoreboard players set z_max int 820000
scoreboard players set base_layer int 50000
function vve:plane/_calc_chunk_range
function vve:plane/_calc_nvec
function vve:plane/_model
data modify storage vve:io input set from storage vve:io result
function vve:plane/_new
```

`_calc_chunk_range` 把四个端点换算成区块号写进 `chunk_*`，`_calc_nvec` 写 `nvec_*`；两个都要在 `_model` 之前跑。`_calc_nvec` 不需要执行实体；`slope_xp` 的同名函数要以 marker 为执行者，所以那边用 `execute as`。

`_new` 在 `0 8 0` 生成 marker 并打上 `result`，之后用 `@e[tag=result,limit=1]` 取它。`result` 只指向最近一次 `_new` 出来的对象，别的模块调 `_new` 会把标签转走。

这组数值只是示例，没有在游戏里跑过。`init` 里 `_class` 之前那行 `vve:plane/_consts` 指向一个不存在的文件，运行时会报 unknown function；`slope_xp`、`point` 等十几个模块也都是这个状态，项目里照常在用。要给平面加常量时补一个 `_consts.mcfunction`。

## 展示

可选，用来看生成结果。必须紧接在生成代码后面跑，中间不能再调 `_new`，否则 `result` 已经不在平面上了。

```
execute as @e[tag=result,limit=1] run function vve:plane/_get
function vve:plane/_update_display
item replace entity @e[tag=result,limit=1] container.0 with glass
```

`_update_display` 生成一块 `item_display` 薄板，带 `tag=vve_slope_display`。第一步的 `result` 还在平面实例上，`_get` 因此读得到实例数据；`_update_display` 内部调 `vve:slope_display/_new`，`result` 在那一步转到展示实体，第三步的 `@e[tag=result]` 已经是展示。`glass` 只是让展示可见，可以换成自己的物品，不参与碰撞。

展示需要 `vve:slope_display` 模块已初始化，`w`、`l`、`h`、`theta` 这四个目标由它创建。

展示是一次性预览。它和平面实例之间没有绑定字段：`_shift_vec` 平移平面不会带走它，重复调 `_update_display` 会再生成一块而不删旧的。

## 在介质探测函数中探测平面

平面的 marker 不带 `vve_material_box` 标签（`cube`、`cublock` 那类才带），`_detect_*` 里现成那一行抓不到它：

```
execute as @e[tag=vve_material_box,dx=0,dy=0,dz=0] positioned ~-0.9999 ~-0.9999 ~-0.9999 if entity @s[dx=0,dy=0,dz=0] run function vve:call_material
```

平面和斜面一样是区块索引介质：先按碰撞点所在区块筛候选，再逐个调用。在 `_detect_material` 的 `# 补充非方块介质` 位置插入，放在现有 `tag=vve_material_box` 那一行之前：

```
# 碰撞点所在的区块
scoreboard players operation chunk_x int = c_x int
scoreboard players operation chunk_z int = c_z int
scoreboard players operation chunk_x int /= 10000 int
scoreboard players operation chunk_z int /= 10000 int
scoreboard players operation chunk_x int /= 16 int
scoreboard players operation chunk_z int /= 16 int
# 该区块内的平面介质
execute as @e[tag=vve_plane,x=0,y=8,z=0,distance=..1,predicate=vve:match_chunk] run function vve:call_material
execute if score material_response int matches 1.. run return fail
```

`chunk_x`、`chunk_z` 是 `int` 目标上的假玩家，`vve:match_chunk` 拿它和每个实例的 `chunk_*` 比较，只看分数不看标签。

`_new` 把 marker 生成在 `0 8 0`，平面高度只存在 `y` 分数里，所以查询锚点是 `x=0,y=8,z=0`，与 `y=64` 无关。

选择器里的 `tag=vve_plane` 决定查不查斜面。去掉它，同区块的斜面也会被一起调用。如果你的 `_detect_material` 已经有一段斜面的区块查询，而且那段选择器不带介质 tag，平面其实已经被覆盖，不要再插一遍。

`vve:call_material` 先看 `@s vve_material_type`：`1` 走 `vve:cube/check_material`，`2` 走 `vve:cublock/check_material`，其余交给 `module_control:_call_method check_material`。平面是 `3`，走最后这条。`module_id` 由 `set_operation` 从 `#vve:plane/ module_id` 复制到实例，那个分数是 `init_operation` 注册时写的，所以 `init` 必须跑过。接完可以 `scoreboard players get #vve:plane/ module_id`，能 get 到分数就说明 `init` 跑过了。

代码块最后那行 `return fail` 要跟着插：`material_response` 是正数就说明本点已由实体介质响应，当前函数到此为止，不再按方块介质重算。所以这段要放在 `_detect_material` 这类最外层探测函数里；放进自己写的子函数时，`return fail` 只退出那个子函数。`_detect_material` 里原本还有一行同样的 `return fail`，守的是它上面的 `vve_material_box` 查询，两行都要留。

命中后调的是 `vve:slope_xp/response`，那份文件的注释里也列了 `vve:plane/check_material`，是有意复用。它有个顺序问题：第 17 行先用临时量 `nvec_y int` 算 `shift_y`，第 22 行才从 `@s nvec_y` 载入。结果就是冲量和摩擦用的是平面的真实法向量，位移那一路不是。

`plane/check_material` 自己不写临时量 `nvec_*`，临时量也不会每帧重置，所以它可能是上一次 `cublock/_get` 或 `vehicle/_get` 留下的别人的法向量——cublock 的 `nvec` 是它上一次接触时按接触方向取的一条自身轴。一个上次贴着墙的 cublock 落到平面上，临时量还停在 `(10000, 0, 0)`，`shift_y` 就变成 0，垂直修正消失。要避开可以在 `plane/check_material` 开头先调 `vve:plane/_get`，把实例的 `nvec` 同步进临时量，不过那是改模块，不是用法。

同一次 `@e` 调用里有多块平面都命中时，它们会被依次调用，后命中的覆盖先命中的；没命中的不会清除已有响应。要只让一块生效，调用前用更窄的选择器或 tag 限定。平面命中后那行 `return fail` 已经让后面的 `vve_material_box` 查询不执行，所以平面和带标签的实体介质之间是平面优先。

## 平移平面

`_shift_vec` 改临时坐标并重算区块范围，不动实例，要接着 `_store` 才写回。下面假设场景里只有一块平面：

```
execute as @e[tag=vve_plane,limit=1] run function vve:plane/_get
scoreboard players set vec_x int 0
scoreboard players set vec_y int 5000
scoreboard players set vec_z int 0
function vve:plane/_shift_vec
execute as @e[tag=vve_plane,limit=1] run function vve:plane/_store
```

`_get` 和 `_store` 都要以实例为执行者，`_shift_vec` 只用全局临时量。它连 `y` 一起平移，升降平台也用这套。

多块平面时不要依赖 `limit=1` 的默认排序，先给目标加自己的 tag：

```
tag @e[tag=result,limit=1] add my_plane
```

后续用 `@e[tag=my_plane]` 选它。展示不跟着平移，旧薄板会留在原位。

## 销毁平面

单块销毁，用上一节的 `my_plane`；没加过就先 `tag @e[tag=vve_plane,limit=1] add my_plane`：

```
execute as @e[tag=my_plane] run function vve:plane/_del
```

`vve:plane/_del` 只是 `kill @s`。

清空场景里的全部平面：

```
kill @e[tag=vve_plane]
```

展示实体不随平面一起消失，要单独清：

```
execute as @e[tag=vve_slope_display] run function vve:slope_display/_del
```

最后一条会连 `slope_xp` 等斜面的展示一起清掉。展示实体和平面实例之间没有绑定字段，没法只删某一块平面的展示；要保留斜面展示就别全量清。
