# 方块读取阵列

`vve:block_reader` 是一个把世界方块区域异步复制到工作区、逐层扫描并通过回调返回方块数据的读取器。

源码目录：`data/vve/function/block_reader/`。

本页只介绍读取器本身，不介绍 `block_reader/test/build_model/` 测试模型。

## 1. 工作区和初始化

读取器使用一个固定的远端工作区，默认数据为：

```text
block_reader_pos  = [300000, -64, 0]
block_reader_size = 3
```

`vve:block_reader/_init` 不是 `vve:_init` 的一部分，需要手动调用：

```mcfunction
function vve:block_reader/_init
```

初始化会：

1. 清空任务队列、任务字典和工作编号；
2. 创建最多 128 个可用工作编号；
3. 准备箭矢回调模块；
4. 对工作区区块执行 `forceload add`；
5. 异步等待区块加载完成；
6. 在工作区周围放置屏障，保护读取器自身。

初始化完成前不要追加读取任务。若区块尚未加载，`init_async` 会每游戏刻重新检查。

## 2. 主程序

`vve:block_reader/main` 是异步主循环：

```mcfunction
function vve:block_reader/main
```

它会：

- 在有空闲工作编号时启动待处理任务；
- 检查落入方块的读取箭矢并调用方块回调；
- 回收已经完成的工作编号；
- 每游戏刻重新计划自身。

读取器最多同时处理 128 个工作编号。任务过多时会留在 `block_reader_tasks`，不会阻塞当前命令链。

## 3. 任务接口

### 3.1 添加普通任务

把任务数据模板写入 `storage vve:io input`，然后调用：

```mcfunction
function vve:block_reader/_append_task
```

一个任务描述一个水平 Y 层，至少需要包含：

```snbt
{
    y_start: 0,
    y: 0,
    x_min: 0.0d,
    z_min: 0.0d,
    x_max: 0.0d,
    z_max: 0.0d,
    run_func: "example:read_block"
}
```

`run_func` 是逐方块回调函数 ID。任务加入后，读取器会自动计划 `main`。

### 3.2 添加带结束回调的任务

先准备任务 `input`，再准备结束回调 `storage vve:io over_func`：

```mcfunction
data modify storage vve:io over_func set value "example:read_over"
function vve:block_reader/_append_task_over
```

结束回调在任务的所有工作编号回收后调用。回调执行期间 `res` 和 `loop` 记分板暂时被读取器占用，不应覆盖它们。

### 3.3 根据区域对角点添加任务

`vve:block_reader/_append_corner` 根据执行位置与执行实体位置确定一个长方体区域，并按 Y 层把它拆成多个读取任务：

```mcfunction
data modify storage vve:io run_func set value "example:read_block"
data modify storage vve:io over_func set value "example:read_over"
execute as @e[tag=math_marker,limit=1] positioned 0 80 0 run function vve:block_reader/_append_corner
```

调用前，执行实体位于一个对角点，`execute positioned` 提供另一个对角点。函数会自动交换大小颠倒的坐标，并把结束回调只挂到最后一层任务上。

需要先构造任务列表、稍后再提交时，可以调用：

```mcfunction
function vve:block_reader/task/_corner_list
```

它使用相同的输入约定，把任务列表输出到 `storage vve:io result`，但不会直接启动读取器。

## 4. 回调协议

逐方块回调通过宏函数调用：

```mcfunction
$function $(run_func)
```

回调执行者是落入当前方块的读取箭矢，方块状态保存在该箭矢的 `inBlockState` 中。回调可以读取箭矢坐标和 NBT，再把结果写入自己的 storage。

读取器内部还提供：

| 函数 | 作用 |
| --- | --- |
| `call_func` | 调用任务的逐方块回调 |
| `call_over_func` | 调用任务结束回调 |
| `get_task` | 从任务字典读取指定工作编号的数据到 `storage vve:io result` |
| `store_task` | 把当前任务写入任务字典 |

## 5. 读取流程

一个任务的执行过程为：

```text
任务进入 block_reader_tasks
    ↓
分配工作编号
    ↓
把任务区域 clone 到工作区
    ↓
按层扫描区域并生成读取箭矢
    ↓
箭矢进入方块后调用 run_func
    ↓
所有箭矢回收后调用 over_func
    ↓
归还工作编号
```

工作区在任务之间会被清空。读取器的方块数据来自 clone 后的工作区，不应在读取过程中修改该区域。

## 6. 卸载

读取器不再使用时手动调用：

```mcfunction
function vve:block_reader/_uninstall
```

卸载会清除工作区屏障、填充的空气以及工作区区块的 `forceload`。它不会自动清空调用者创建的任务数据，也不会删除调用者自己的回调函数。

## 7. 当前限制

1. 工作区坐标和大小是全局 storage，不支持多个读取器实例并行运行。
2. 读取器依赖 `math_marker` 作为工作区遍历实体。
3. `run_func` 和 `over_func` 使用宏调用，必须是有效的函数 ID。
4. `res`、`loop`、`inp` 等记分板在内部循环中被占用，回调应避免依赖或覆盖这些临时值。
5. 读取器只返回方块状态和扫描坐标，不负责把结果自动转换为物理模型。
