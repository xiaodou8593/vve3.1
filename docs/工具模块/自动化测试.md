# 自动化测试

VVE 的自动化测试工具由两个模块组成：

- `data/vve/function/test_auto/`：测试队列、计时器和生命周期调度；
- `data/vve/function/test_coord/`：测试坐标的保存、投射、传送和显示。

根目录的 `vve:_test_auto` 是一个便捷启动入口。测试用例本身位于 `data/vve/function/test/` 或各示例模块的 `test/` 目录，但本页不把具体测试模型当作工具模块介绍。

## 1. 快速启动

项目提供的完整入口是：

```mcfunction
function vve:_test_auto
```

该入口要求玩家为执行者，并且需要 `math3.1_gelib`。它会：

1. 初始化数学库、线性代数库、图形库和 VVE；
2. 初始化方块读取器；
3. 把测试坐标设置到 `(0,100,0)` 附近；
4. 准备测试地面和观察位置；
5. 写入一组测试前缀到 `storage vve:io test_pointers`；
6. 调用 `vve:test_auto/_start`。

普通模块也可以跳过根入口，直接自己准备测试列表，再启动 `test_auto`。

## 2. 测试调度器

### 2.1 初始化

`vve:test_auto/init` 由 `vve:_init` 调用，初始化：

```text
storage vve:io test_pointers = []
storage vve:io test_timer = 0
storage vve:io test_max_time = 75
```

### 2.2 启动和停止

```mcfunction
function vve:test_auto/_start
function vve:test_auto/_stop
```

`_start` 把 `test` 记分板设为 `1`，给当前测试 20 tick 的启动阶段，并计划每 tick 执行一次 `test_auto/main`。

`_stop` 清除 `test_auto/main` 的计划，但不会清理当前测试实体、测试场地或测试 storage。清理工作由各测试自己的 `end` 函数负责。

### 2.3 测试队列

队列元素是带结尾斜杠的函数前缀，例如：

```snbt
[
    "vve:test/point/",
    "vve:test/float/"
]
```

`start_next_test` 取出队首前缀，把它写入 `test_pointer`，再通过宏调用：

```mcfunction
$function $(test_pointer)start
```

所以每个测试前缀必须提供 `start` 函数。

## 3. 生命周期

一个测试通常包含：

```text
start → main（逐 tick）→ store_frame / frame → end
```

调度器的状态转换如下：

- `test = -1`：正在运行当前测试；
- `test = 1`：当前测试已结束，等待结束阶段或下一个测试；
- `test_timer`：当前阶段剩余 tick 数。

当计时器归零时：

1. 如果当前测试仍未结束，调用 `stop_cur_test`，给它 20 tick 的结束阶段；
2. 如果当前测试结束且队列为空，输出 `done` 并停止后续测试切换；
3. 如果仍有队列元素，调用下一个测试的 `start`。

每个测试应自行在 `end` 中销毁实例、恢复场地和清除临时实体。

## 4. 测试坐标模块

`vve:test_coord` 使用三个记分板保存测试基准坐标：

```text
vve_test_x
vve_test_y
vve_test_z
```

### 4.1 设置坐标

```mcfunction
function vve:test_coord/_set_here
function vve:test_coord/_set_here_align
```

两者都要求执行者是玩家或世界实体。`_set_here` 直接记录当前位置；`_set_here_align` 会先把执行者对齐到方块中心，再记录坐标。

### 4.2 传送和渲染

```mcfunction
function vve:test_coord/_topos
function vve:test_coord/_tp_here
function vve:test_coord/_render
```

`_topos` 把当前执行者传送到测试坐标；`_tp_here` 先让工作实体到达测试坐标，再把调用者传送到那里；`_render` 会把当前执行世界实体移到测试坐标，并在那里生成灵魂火焰粒子。

### 4.3 数据模板接口

测试坐标可以通过 `storage vve:io input/result` 转换：

```mcfunction
function vve:test_coord/_proj
function vve:test_coord/_model
```

输入模板格式为：

```snbt
{center: [0.0d, 0.0d, 0.0d]}
```

`_get_relative` 读取当前执行位置与测试基准的差值，并把它格式化为可点击复制的相对坐标命令。该函数内部会移动 UUID 为 `0-0-0-0-0` 的工作实体。

## 5. 编写测试用例

测试前缀至少应提供：

```text
start
main
end
```

需要帧基线时，再增加 `store_frame` 和 `frame`。测试的 `start` 负责创建实例和准备场地，`main` 负责逐 tick 调用被测模块，`end` 负责清理。

队列示例：

```mcfunction
data modify storage vve:io test_pointers set value [
    "example:test/fall/",
    "example:test/push/"
]
function vve:test_auto/_start
```

## 6. 运行边界

1. 自动化测试会修改方块、全局常量、storage 和测试实体，只应在专用测试区域运行。
2. 测试坐标、测试计时器和队列都是共享状态，不支持多个自动测试同时运行。
3. `math3.1_gelib` 只用于轨迹、响应或坐标可视化；不安装它时，不应调用根入口 `_test_auto`。
4. 测试调度器不会判断物理结果是否正确；正确性由 `frame` 或测试自己的断言逻辑决定。
5. 队列正常完成时，`test_auto/main` 会在再次计划前返回；提前中止测试时应调用 `_stop` 清除计划任务。
