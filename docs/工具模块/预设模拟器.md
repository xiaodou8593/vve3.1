# 预设模拟器

`vve:simulator` 是 VVE 内置的全局模拟器。它保存一组模拟时间状态和回调函数列表，在每个游戏刻加载 VVE 默认常量、执行若干物理子步，并在结束时执行同步回调。

源码目录：`data/vve/function/simulator/`。

预设模拟器适合直接调度已经提供 `tick` 或 `main*` 接口的物体。需要独立物理常量或独立调度集合时，应使用 `vve_simulator_1.0` 模板构建自定义模拟器，而不是复制本页函数后直接修改共享状态。

## 1. 初始化和运行

`vve:simulator/init` 由 `vve:_init` 调用，清空两类回调并生成默认数据模板。默认模板位于：

```text
storage vve:io simulator_plate
```

默认状态为：

```snbt
{
    global_sim_mod: 0,
    global_inv_dt: 1,
    global_set_inv_dt: 1,
    global_rate: 1,
    tick_funcs: [],
    sync_funcs: []
}
```

开始和停止调度：

```mcfunction
function vve:simulator/_start
function vve:simulator/_stop
```

`_start` 计划 `vve:simulator/tick` 每游戏刻运行一次；`_stop` 清除该计划。`global_rate = 0` 只是暂停模拟子步，并不等同于 `_stop`。

## 2. 一次主循环

`vve:simulator/tick` 调用 `vve:simulator/main`，然后重新计划下一游戏刻。`vve:simulator/main` 的流程是：

```text
_get
  ↓
_consts
  ↓
执行 global_rate 次 main_loop
  ↓
执行一次 sync_funcs
  ↓
_store
```

`main_loop` 每次递归执行一个子步：

1. `global_sim_mod` 加一；
2. 运行全部 `tick_funcs`；
3. 对 `global_sim_mod` 按 `global_inv_dt` 取模；
4. 在周期相位回到零时，把 `global_set_inv_dt` 应用到 `global_inv_dt`；
5. 继续执行剩余子步。

因此，`tick_funcs` 在每个子步运行，`sync_funcs` 每游戏刻最多运行一次。

## 3. 时间倍率

模拟时间倍率为：

```text
global_rate / global_inv_dt
```

| `global_rate` | `global_inv_dt` | 效果 |
| ---: | ---: | --- |
| `1` | `1` | 正常速度 |
| `4` | `1` | 每游戏刻执行四个完整物理步 |
| `1` | `4` | 一个物理步拆成四个游戏刻 |
| `0` | 任意正数 | 暂停物理子步 |

修改拆分数时，应写入 `global_set_inv_dt`，让模拟器在当前周期结束后切换。不要在运行中的任意相位直接覆盖 `global_inv_dt`。

## 4. 模拟器数据接口

### 4.1 临时对象转换

```mcfunction
function vve:simulator/_get
function vve:simulator/_store
```

`_get` 把 `storage vve:io simulator_plate` 投射到共享临时对象；`_store` 把临时对象重新建模并写回同一位置。直接修改模拟器状态的完整流程应保持为 `_get → 修改 → _store`。

### 4.2 回调列表

回调函数 ID 通过 `storage vve:io input` 传入：

```mcfunction
function vve:simulator/_get
data modify storage vve:io input set value "example:object/tick"
function vve:simulator/_append_tick_func
function vve:simulator/_store
```

接口如下：

| 接口 | 输入 | 输出 `res` |
| --- | --- | --- |
| `_append_tick_func` | `input` 中的函数 ID | 已存在时为 `1`，否则追加 |
| `_find_tick_func` | `input` 中的函数 ID | 存在为 `1` |
| `_remove_tick_func` | `input` 中的函数 ID | 成功移除为 `1` |
| `_clear_tick_funcs` | 无 | 清空 `tick_funcs` |
| `_append_sync_func` | `input` 中的函数 ID | 已存在时为 `1`，否则追加 |
| `_find_sync_func` | `input` 中的函数 ID | 存在为 `1` |
| `_remove_sync_func` | `input` 中的函数 ID | 成功移除为 `1` |
| `_clear_sync_funcs` | 无 | 清空 `sync_funcs` |
| `_clear` | 无 | 同时清空两类回调 |

追加接口会先查询，重复注册会提前返回，不会写入重复项。

## 5. 常量隔离

`simulator/_consts` 每轮先调用 `vve:_consts`，再预留位置覆盖本模拟器的常量。因此自定义模拟器必须保留这个顺序：

```mcfunction
function vve:_consts
scoreboard players set vve_gravity int 120
```

预设模拟器和自定义模拟器共享底层临时记分板，只能依次完成一整轮 `_get → main → _store`。不要在一个模拟器尚未保存时嵌套运行另一个模拟器。

## 6. 常见错误

1. 把 `global_rate` 当作持久配置以外的递归计数器。主循环会在递归返回时恢复它。
2. 同一物体同时加入多个模拟器，导致重复物理迭代。
3. 只覆盖少数常量而不先调用 `vve:_consts`，使前一个模拟环境的参数残留。
4. 在 `sync_funcs` 中再次执行物理主程序，造成一游戏刻内重复计算。
5. 只调用 `_start` 不调用 `_stop`，导致模拟器在测试结束后继续被计划执行。
